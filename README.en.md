## Intro
- This is a GoTTY-compatible server rewritten in JavaScript / Bun.
- It is based on the original GoTTY code, with most of the new code generated by Codex.
- It includes a frontend and WebTTY protocol implementation adjusted for `js-gotty`.
- Original repository:
- https://github.com/sorenisanerd/gotty

### Features
- Resumable reconnect: after the browser disconnects, you can reconnect to the original shell / PTY with a reconnect token instead of spawning a new shell.
- Kitty Graphics Protocol: displays inline terminal images.
  * For example, `bun viu.mjs 1.png` shows an image directly in the terminal.
  * Windows does not use Kitty protocol; it uses a custom protocol.
- ZMODEM / `rz/sz`: select files in the browser and upload them to the remote shell.
  * You can also download files from the remote shell.
  * Windows does not use ZMODEM; it uses a custom protocol.

### PTY backends
- Linux / macOS: use Bun's built-in PTY via `Bun.spawn(..., { terminal: ... })`
- Windows: use patched `node-pty`, while still launching `gotty.js` through `bun`
  * The goal is to move fully to Bun in the future

## Usage

### Install Bun
- Android / Termux:
  * `pkg install npm`
  * `npm install -g bun`
- Other platforms:
  * https://bun.com

### Linux

```sh
bun gotty.js -w bash
bun gotty.js -w --credential user:pass bash
bun gotty.js -w --reconnect fish
bun gotty.js -w --reconnect --reconnect-time 30 fish
bun gotty.js -w --reconnect --reconnect-time -1 fish
bun gotty.js -w -p 8000 fish

# or npx jsgotty@latest

# show help
bun gotty.js
```

### Windows

```sh
bun gotty.js -w cmd.exe
bun gotty.js -w powershell

# or npx jsgotty@latest

# show help
bun gotty.js
bun gotty.js -h
```

### Built-in tools

```sh
bun gotty.js --rz
bun gotty.js --sz
bun gotty.js --viu
bun gotty.js --client
```

- `--rz` starts `rz.js`
- `--sz` starts `sz.js`
- `--viu` starts `viu.mjs`
- `--client` starts `client.mjs`

### CLI Client

`client.mjs` is an interactive terminal client that connects directly to GoTTY. Basic connections are compatible with Golang GoTTY. Session listing, writer management, and remote PTY termination require this project's js-gotty server.

```sh
# Connect to the default ws://127.0.0.1:8080/ws
bun gotty.js --client

# Connect to 127.0.0.1:8081
bun gotty.js --client 8081

# HTTP(S) page URLs and WS(S) URLs are accepted
bun gotty.js --client https://example.com/terminal/

# Connect with credentials
bun gotty.js --client -c user:pass 8081
```

The first writable client becomes the writer, while additional connections are read-only viewers. Use `--readonly` to connect explicitly as a viewer. The client reports the session PID, reconnect token, and its current writer/viewer role.

```sh
# Resume an existing session by reconnect token or PID
bun gotty.js --client -r <token|pid> [target]

# List current sessions
bun gotty.js --client -ls [target]

# Disconnect the current writer while keeping the PTY session alive
bun gotty.js --client -d <token|pid> [target]

# Terminate the matching PTY session
bun gotty.js --client -k <token|pid> [target]
```

- `-r` resumes an existing session; lookup by PID is a js-gotty extension.
- `-ls` reads the server's `/css.md` session list.
- Open `/css` to view the session list in a browser.
- If `/css` shows a static file list instead of sessions, the server is Golang GoTTY, not js-gotty.
- `-d` requires `--reconnect` on the server. The session remains alive after its writer is disconnected, allowing another client to take over.
- `-k` terminates the matching PTY/session.
- `--arg <value>` may be repeated to pass command arguments; `--arguments <query>` passes a raw query string.
- `--cols` and `--rows` set the initial terminal size.
- `GOTTY_CREDENTIAL` and `GOTTY_RECONNECT_TOKEN` may be used to configure credentials and the reconnect token.
- Golang GoTTY does not support the js-gotty control protocols used by `-ls`, `-d`, and `-k`.

## Current implementation
- Uses Node's built-in `http` / `https`
- Uses `ws` for WebSocket upgrade handling
- Uses bundled frontend assets in `./static`, including kitty overlay and WebTTY / ZMODEM frontend logic
- Supports reconnect tokens and session resume
- Supports inline terminal images
- Supports file upload / download

### Reconnect / Resume
- `--reconnect` is not just reopening a websocket. The server keeps the current PTY session alive so the browser can reconnect to the original shell.
- The server generates a reconnect token for each reconnectable session. The frontend stores this token automatically and prefers it on reconnect.
- `--reconnect-time` semantics:
  * `> 0`: keep the session alive for the specified number of seconds after disconnect
  * `= 0`: do not keep the session alive
  * `< 0`: keep the session alive indefinitely until the shell exits or the server stops
- Frontend reconnect behavior:
  * when `reconnect-time > 0`, it retries automatically several times within the timeout
  * when `reconnect-time < 0`, it retries once per minute
  * the overlay provides a `Reconnect` button for immediate manual retry
  * right-click / long-press on that button lets you enter a custom reconnect token
- Reconnect is "reconnect to the existing shell", not "replay all output during the disconnect window". Output produced while disconnected is not replayed.
- When `--reconnect` is disabled, `/css` and `/css.md` still show PID / command name, but they do not provide reconnect tokens or links.

### Kitty intro
- If the terminal program outputs images using Kitty Graphics Protocol on Linux, the frontend displays those images at the corresponding terminal position.
- Windows uses a custom protocol.
- Usage:

```sh
bun viu.mjs 1.png
```

### rz upload intro
- When the remote shell runs:

```sh
bun rz.js
```

- The frontend opens a file picker. After selecting files, they are uploaded to the current shell directory using ZMODEM.

### sz download intro
- When the remote shell runs:

```sh
bun sz.js file.txt
```

- The frontend receives the ZMODEM download data and lets the browser download the file.

## Notes
- The goal is to emulate the main behavior of the original GoTTY and add additional features.
- Bun is the primary runtime.
- On Linux / macOS, PTY support will not work unless the program is launched with Bun.
- GoTTY config file loading is not implemented yet.
